# CI/CD FlashTicket Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Push lên `main` chỉ verify, build image, deploy lại đúng container của service bị sửa trên máy 84 (8 service: 7 Spring + Keycloak), có health check và tự rollback.

**Architecture:** Một registry `.github/services.json` mô tả 8 service. `detect-changes.sh` / `plan-deploy.sh` đổi diff hoặc input dispatch thành danh sách service. `cd.yml` gọi reusable `_deploy-service.yml` (verify → build/push GHCR theo digest → SSH chạy một script `deploy-service.sh` duy nhất trên 84). Mọi script đều có test bash chạy với docker/curl giả.

**Tech Stack:** GitHub Actions (reusable workflow), bash + jq, Docker Compose 2.40 (`extends`, `--env-file`), Maven Wrapper / Maven, GHCR, Eureka REST.

**Spec:** [docs/superpowers/specs/2026-11-07-cicd-design.md](../specs/2026-11-07-cicd-design.md). Plan này đổi hai điểm so với spec (đã được Sơn chọn trong phiên 2026-11-07): `keycloak-spi` là service thứ 8, và danh sách service nằm ở `services.json` thay vì `service-filters.yml`. Task 13 cập nhật spec cho khớp.

## Global Constraints

- Mọi Spring service dùng Java 21: `<java.version>21</java.version>`, enforcer `[21,22)`, base image `eclipse-temurin:21-jre-alpine@sha256:b48e02e0ea88d7bfb305335df94923bdef394905f4147dccd52e873cf17b1088`.
- Image bất biến: deploy bằng digest `image@sha256:...`, tag `sha-<commit>`, label OCI `source` và `revision=<commit>`. Server không bao giờ build từ source.
- Registry: `ghcr.io/levanminh04/flash-ticket-platform/<service>`, đăng nhập bằng `GITHUB_TOKEN`.
- Port không đổi: api-gateway 8081, booking 8082, payment 8083, ticket 8084, user 8085, event 8086, discovery-server 8761, keycloak 8080.
- Nhánh deploy duy nhất là `main`; GitHub Environment `production`.
- Thư mục trên 84: `/opt/flash-ticket-app/{compose,env,secrets/ticket-qr,state}` + `deploy-service.sh`. `env/<svc>.env` mode 600; CI không bao giờ ghi vào `env/` hoặc `secrets/`.
- Mỗi service là một Compose project `flash-ticket-<svc>`.
- Health check tối đa 180 s. Thiếu RAM (`MemAvailable` < `mem_limit`) thì dừng với `INSUFFICIENT_MEMORY`, không recreate. OOM báo `OOM_KILLED`.
- Deploy tuần tự (`max-parallel: 1`), discovery-server trước. `concurrency` theo service, `cancel-in-progress: false`.
- `mem_limit`: api-gateway 768m, discovery-server 384m, user 768m, event 512m, ticket 768m, booking 512m, payment 512m, ngrok 128m, keycloak 768m.
- Action bên thứ ba pin theo commit SHA.
- Máy 119 bỏ hẳn: không deploy, không dọn, xóa mọi `FT119_*`.
- **Không commit, không push** cho tới khi Sơn cho phép (yêu cầu của Sơn ngày 2026-11-07: "chưa cần commit vội"). Mỗi task kết thúc bằng checkpoint `git status --short -- <path>`.
- **Cây làm việc dùng chung với worker AO 19–22 và đang có ~87 file chưa commit của người khác.** Chỉ sửa đúng file trong mục **Files** của task. Cấm `git add -A`, `git stash`, `git checkout -- .`, `git clean`, `git reset --hard`.
- Script `.sh` phải LF (repo đặt `* text=auto eol=lf`). Test bash chạy trên Linux: `wsl bash deploy/tests/run-all.sh` (WSL Ubuntu 24.04 đã có `flock`, `docker`, `git`, `curl`; **thiếu `jq` và `shellcheck`**: chạy `wsl sudo apt-get install -y jq shellcheck`, nếu không có quyền sudo thì chỉ chạy test trong CI).

## Review Focus

Năm điều spec ngầm yêu cầu nhưng dễ bị bỏ qua. Mỗi dòng có test ở task ghi trong ngoặc.

1. Push chỉ sửa `.md`/`.env.example`, hoặc `before` là `000…0`, hoặc commit `before` không còn trong lịch sử (force-push): chỉ-`.md` thì không deploy gì; hai trường hợp còn lại build cả 8 service thay vì lỗi. (Task 9)
2. Sau `up -d` instance Eureka của container cũ vẫn `UP` thêm tối đa 90 s: health check không được qua nhầm. Phải đòi `registrationTimestamp` ≥ lúc container mới start. (Task 8)
3. Thiếu/ sai mode `env/<svc>.env`, thiếu token trên stdin, image khác repo hoặc khác service: từ chối trước khi đụng container. (Task 8)
4. `workflow_dispatch` với rollback `all`, digest sai định dạng, service không tồn tại, action lạ: dừng ở bước plan, không chạm server. (Task 10)
5. Máy thiếu RAM: `INSUFFICIENT_MEMORY` và container cũ vẫn chạy nguyên; container bị OOM khi deploy vẫn được rollback kèm lý do `OOM_KILLED`. (Task 8)

```bash
# Usage: deploy-service.sh <service> <ghcr-image@sha256:digest> <commit>     (GHCR token on stdin)
# Env:   REGISTRY_USER (required), APP_ROOT (default /opt/flash-ticket-app)
# First output line of interest: DEPLOY_SUCCESS | ROLLED_BACK <why> | DEPLOY_FAILED <why> | DEPLOY_REJECTED <why>
set -euo pipefail

APP_ROOT=${APP_ROOT:-/opt/flash-ticket-app}
MEMINFO_FILE=${MEMINFO_FILE:-/proc/meminfo}
HEALTH_TIMEOUT=${HEALTH_TIMEOUT:-180}
POLL_SECONDS=${POLL_SECONDS:-5}

  [ticket-service]=8084 [booking-service]=8082 [payment-service]=8083 [keycloak]=8080
)

reject() { echo "DEPLOY_REJECTED $*"; exit 64; }

svc=${1:-}; image=${2:-}; commit=${3:-}
[[ -n $svc && -v PORT[$svc] ]] || reject "unknown service '$svc'"
[[ $image =~ ^$REPO/$svc@sha256:[a-f0-9]{64}$ ]] || reject "image must be $REPO/$svc@sha256:<digest>"

  || { echo "DEPLOY_FAILED INVALID_COMPOSE"; exit 1; }

fi

dc "$image" pull --quiet "${targets[@]}" || { echo "DEPLOY_FAILED PULL_FAILED"; exit 1; }

recreate() { dc "$1" up -d --no-deps --no-build --force-recreate "${targets[@]}"; }

healthy() { # $1 = container id
  case $svc in
    discovery-server)
      [[ $(curl -fsS -m 5 http://127.0.0.1:8761/actuator/health | jq -r .status) == UP ]] ;;
    keycloak)
      curl -fsS -m 5 -o /dev/null http://127.0.0.1:8080/realms/flash-ticket/.well-known/openid-configuration ;;
    *)
      # Eureka keeps the old container's registration "UP" for up to 90 s, so require one registered after this container started.
      local started_ms
      started_ms=$(( $(date -d "$(docker inspect -f '{{.State.StartedAt}}' "$1")" +%s) * 1000 ))
      curl -fsS -m 5 -H 'Accept: application/json' "http://127.0.0.1:8761/eureka/apps/${svc^^}" |
        jq -e --argjson p "${PORT[$svc]}" --argjson t "$started_ms" \
          '[.application.instance | if type == "array" then .[] else . end
            | select(.status == "UP" and (.port["$"] | tonumber) == $p and .leaseInfo.registrationTimestamp >= $t)]
           | length > 0' > /dev/null ;;
  esac
}

verify() { # $1 = image that must be running; sets $reason and $cid
  local deadline=$((SECONDS + HEALTH_TIMEOUT)) oom restarts running imgid
  while (( SECONDS < deadline )); do
    cid=$(dc "$1" ps -q "$svc" || true)
    if [[ -n $cid ]]; then
      read -r oom restarts running imgid < <(docker inspect -f '{{.State.OOMKilled}} {{.RestartCount}} {{.State.Running}} {{.Image}}' "$cid")
      if [[ $oom == true ]]; then reason=OOM_KILLED; return 1; fi
      if (( restarts > 0 )); then reason=CRASH_LOOP; return 1; fi
      if [[ $running == true && $imgid == "$(docker image inspect -f '{{.Id}}' "$1")" ]] && healthy "$cid"; then
        return 0
      fi
    fi
    sleep "$POLL_SECONDS"
  done
  reason=HEALTH_TIMEOUT
  return 1
}

prune() { # keep only the digests recorded in current/previous
  local keep
  keep=" $(cat "$state.current" 2>/dev/null || true) $(cat "$state.previous" 2>/dev/null || true) "
  docker image ls --digests --format '{{.Repository}}@{{.Digest}}' "$REPO/$svc" |
    while read -r ref; do [[ $keep == *" $ref "* ]] || docker image rm "$ref" > /dev/null || true; done || true
}

recreate "$image"
if verify "$image"; then
  if [[ -n $current && $current != "$image" ]]; then printf '%s' "$current" > "$state.previous"; fi
  printf '%s' "$image" > "$state.current"
  prune
  echo "DEPLOY_SUCCESS $svc $image $commit"
  exit 0
fi

echo "---- last log lines (secrets masked) ----"
# shortcut: regex masking catches common key=value / key: value secrets only; widen it if logs ever carry other formats.
docker logs --tail 50 "$cid" 2>&1 | sed -E 's/((password|secret|token|key)[A-Za-z_]*[=:] *)[^ ,"]+/\1***/Ig' || true
if [[ -z $current ]]; then
  echo "DEPLOY_FAILED $reason (first deploy: no previous digest to roll back to)"; exit 1
fi
recreate "$current"
if verify "$current"; then
  echo "ROLLED_BACK $reason -> $current"
else
  echo "DEPLOY_FAILED $reason (rollback to $current also failed: $reason)"
fi
exit 1
```

```bash
#!/usr/bin/env bash
# Usage: detect-changes.sh <base-sha> <head-sha>
# Prints build=<json> and recreate=<json> (arrays of .github/services.json entries, in deploy order) for $GITHUB_OUTPUT.
#   build    = the service's source changed: verify + image + deploy
#   recreate = only its compose / shared deploy files changed: redeploy the digest already running
set -euo pipefail

base=${1:?base sha}
head=${2:?head sha}
root=$(git rev-parse --show-toplevel)
registry="$root/.github/services.json"

if [[ $base =~ ^0+$ ]] || ! git -C "$root" cat-file -e "$base^{commit}" 2> /dev/null; then
  # first push of a branch or a force-push: no usable base, treat every service as changed
  files=$(jq -r '.services[].path + "/x"' "$registry")
else
  files=$(git -C "$root" diff --name-only "$base" "$head")
fi

declare -A build recreate
while IFS= read -r f; do
  if [[ -z $f || $f == *.md || $f == .env.example || $f == */.env.example ]]; then continue; fi
  while IFS=$'\t' read -r name path; do
    if [[ $f == "$path"/* ]]; then build[$name]=1; fi
    if [[ $f == "deploy/app/$name.yml" ]]; then recreate[$name]=1; fi
    if [[ $f == deploy/app/_common.yml || $f == deploy/scripts/deploy-service.sh ]]; then recreate[$name]=1; fi
  done < <(jq -r '.services[] | [.name, .path] | @tsv' "$registry")
done <<< "$files"

for name in "${!build[@]}"; do unset "recreate[$name]"; done # a rebuilt service is redeployed anyway

pick() { # pick <assoc array name>: matching registry entries as a JSON array
  local -n ref=$1
  jq -c --argjson names "$(jq -nc '$ARGS.positional' --args "${!ref[@]}")" \
    '[.services[] | select(.name as $n | $names | index($n))]' "$registry"
}
echo "build=$(pick build)"
echo "recreate=$(pick recreate)"
```

```bash
#!/usr/bin/env bash
# Decides which services CD touches.
# Env: EVENT_NAME; push: BEFORE, SHA; workflow_dispatch: ACTION (deploy|restart|rollback), SERVICE (name|all), IMAGE_DIGEST.
# Prints first/rest/has_first/has_rest for $GITHUB_OUTPUT. `first` is discovery-server, which must be up before the rest.
set -euo pipefail

here=$(cd "$(dirname "$0")" && pwd)
registry="$here/../services.json"
die() { echo "plan-deploy: $*" >&2; exit 1; }

build='[]'; recreate='[]'; rollback='[]'
if [[ ${EVENT_NAME:-} == push ]]; then
  out=$(bash "$here/detect-changes.sh" "${BEFORE:?BEFORE}" "${SHA:?SHA}")
  build=$(sed -n 's/^build=//p' <<< "$out")
  recreate=$(sed -n 's/^recreate=//p' <<< "$out")
else
  action=${ACTION:-}; service=${SERVICE:-}
  [[ $action == deploy || $action == restart || $action == rollback ]] || die "unknown action '$action'"
  if [[ $service == all ]]; then
    [[ $action != rollback ]] || die "rollback needs exactly one service"
    selected=$(jq -c '.services' "$registry")
  else
    selected=$(jq -c --arg s "$service" '[.services[] | select(.name == $s)]' "$registry")
    [[ $selected != '[]' ]] || die "unknown service '$service'"
  fi
  if [[ $action == rollback && ! ${IMAGE_DIGEST:-} =~ ^sha256:[a-f0-9]{64}$ ]]; then
    die "rollback needs image_digest sha256:<64 hex>"
  fi
  case $action in
    deploy) build=$selected ;;
    restart) recreate=$selected ;;
    rollback) rollback=$selected ;;
  esac
fi

plan=$(jq -nc --argjson b "$build" --argjson r "$recreate" --argjson k "$rollback" \
  --arg d "${IMAGE_DIGEST:-}" --slurpfile reg "$registry" '
  ($b | map(. + {mode: "build-and-deploy"}))
  + ($r | map(. + {mode: "recreate"}))
  + ($k | map(. + {mode: "rollback", image_digest: $d})) as $all
  | [$reg[0].services[] | .name as $n | $all[] | select(.name == $n)]')
first=$(jq -c '[.[] | select(.name == "discovery-server")]' <<< "$plan")
rest=$(jq -c '[.[] | select(.name != "discovery-server")]' <<< "$plan")
echo "first=$first"
echo "rest=$rest"
echo "has_first=$(jq 'length > 0' <<< "$first")"
echo "has_rest=$(jq 'length > 0' <<< "$rest")"
```

**Deploy lần đầu**

1. Merge PR vào `main` (push `main` tự chạy `CD`; các service đổi sẽ deploy).
2. `gh workflow run cd.yml -f action=deploy -f service=all` — thứ tự discovery → gateway → user → event → ticket → booking → payment → keycloak.
3. Smoke trên 84:
   - `curl -s -H 'Accept: application/json' http://127.0.0.1:8761/eureka/apps | jq '[.applications.application[].instance[].status]'` → toàn `UP`.
   - `curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8080/realms/flash-ticket/.well-known/openid-configuration` → `200`.
   - `curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8081/` → `401`/`403`/`404` (không phải lỗi kết nối).
4. Diễn tập rollback: `gh workflow run cd.yml -f action=rollback -f service=event-service -f image_digest=<digest từ state/event-service.previous>` → job xanh, `DEPLOY_SUCCESS`.
